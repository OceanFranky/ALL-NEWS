# 学生资讯与机会平台：四个核心工作板块开发需求

版本：V1.0
日期：2026-10-16（Asia/Shanghai）
状态：四个工作板块已由使用者确认；未确认的来源、分类、视觉、渠道和预算保留为待决定项。
基线：远端 main `8b5fa62`。本文记录下一轮需求，不表示功能已经实现，也不授权开启采集、付费调用、推送或部署。

## 1. 目标与适用范围

保留行业信息、世界新闻和现有竞赛能力，面向学生补齐“了解资讯—找到机会—获取经验与教学—及时行动”的使用流程。本轮四个核心工作板块为：

1. 每个竞赛详情页提供对应经验帖和教学视频。
2. 建设完整的保研／考研板块，同时提供对应经验帖和视频。
3. 重构整站 UI，统一资讯、机会和学习资源的浏览体验。
4. 接入手机 QQ／微信，形成经真实账号验证的查询或通知入口。

本文承接使用者提供的《学生资讯与机会平台需求文档》V0.1，并以2026-10-16的上述四项要求为本轮范围。新增“考研”，不能把升学板块仅实现为保研；竞赛经验与视频是必需交付，不能仅留下后续规划。旧稿中与后续明确决定冲突的内容不恢复：竞赛仍遵守已批准的第一轮字段范围，资源作为关联内容扩展，不顺带新增费用、主办方或专业资格等字段。

## 3. 工作板块一：竞赛经验帖与教学视频

### CR-01 资源关联与详情入口

每个竞赛详情页必须提供“经验帖”和“教学视频”区域。资源关联到稳定竞赛身份，并按需要限定届次、赛段、方向或适用年份；跨届通用资源单独标明，不能把旧届经验描述为当前规则。允许一份资源关联多个对象，关联理由、适用范围与资源正文分开保存。

无可核实资源时显示“暂未收录”，管理员可看到待补清单；不得为凑数编造帖子、视频或对应关系。页面区域上线与资源覆盖率分别验收，只有区域而无资源不算内容目标完成。

### CR-02 经验帖

卡片至少包含标题、作者（未知时明确显示）、平台、原文链接、内容类型、可可靠取得的发布时间／年份、适用竞赛及范围、简短介绍、是否官方、核验状态。区分参赛经历、入门建议、工具教程、赛后复盘；介绍必须有可追溯依据。个人经验不覆盖官方规则，也不自动作为资格、时间或工具使用许可的依据。

### CR-03 教学视频

卡片至少包含标题、作者／机构、平台、原视频链接、教学主题、适用范围；发布时间、时长和封面仅在可靠取得且允许使用时展示。首版支持原平台跳转，不要求播放器嵌入；无授权不下载、转存视频。只有标题／封面时不生成“已看完整段视频”的总结；摘要注明简介、字幕或人工整理等依据。

### CR-04 收录与维护

后台支持录入链接、编辑元数据、关联／解除关联、审核发布／撤回、标记失效及记录原因。支持人工精选起步；自动发现使用哪些平台、作者、关键词和筛选标准由使用者确认，不能据本文扩展采集范围或预算。相同资源避免重复收录，区分资源失效与暂时访问失败。

前台区分经验与官方通知；过时或不适用于当前届的资源提示范围，撤回后所有公开入口停止提供。比赛期间的当届答案、代做或可能违反规则的内容不自动推荐，依据当届官方规则处理。

### CR-05 验收

- 首批逐项检查现有31项竞赛详情的两类区域和正确关联；逐项列出真实经验帖数、视频数及未补齐原因，数量指标待来源摸底后确认。
- 使用真实样例覆盖通用／专属届次、跨届旧经验、同资源多关联、链接失效、无资源及撤回；资源不能串到错误竞赛或赛段。
- 手机可以看清来源、适用范围并打开原平台；从资源返回不丢失竞赛上下文。
- 管理员完成录入→审核→公开展示→撤回的全过程；操作有记录，读者访问不触发模型。

## 4. 工作板块二：保研／考研与关联资源

### AD-01 信息架构与业务边界

提供统一升学入口，保研、考研分别组织和筛选，具体导航名称待UI方案确认。共享学校、院系、专业、年份、材料和资源基础；业务阶段、时间状态和公告类型分别建模，不能把考研当成保研的一个批次，也不能套用新闻近期热度来判断机会是否有效。

保研首版候选范围为夏令营、预推免、正式推免接收、招生说明、材料与考核通知；是否纳入本校推免资格政策待确认。考研首版候选范围为招生简章、专业目录、报名相关公告、初试安排、复试与录取相关通知、调剂信息。以上为范围提案，首批具体学校／院系／专业、公告类别和来源须由使用者确认，不能承诺全院校覆盖。

### AD-02 对象、字段与来源

以学校／院系／专业或项目／招生年度／升学类型／阶段及批次确定具体机会身份，公告、附件、变更和资源关联到该身份。学校总通知与院系细则同时保留；同一公告涉及多个项目时保留适用范围。招生年度与网页发布时间分开，不凭发布年份补招生年度。

详情支持名称、学校、院系、专业／项目、招生年度、保研／考研类型、阶段／批次、官方公布的申请条件、材料清单、报名／申请及考核时间、官方入口与附件、当前状态、来源、核验时间、变更记录。硕士／直博等培养类型仅据官方材料记录；考研科目、参考书目、复试要求等差异字段是否纳入首版，在代表性真实样本核对后确定。

优先采用经确认的官方招生站、研究生院和院系来源；经验平台与官方来源分开管理。关键日期、条件和材料关联原文及证据位置，缺失／冲突保留待核验。扫描件或表格解析不完整不能标成全部读取成功。

### AD-03 页面与用户流程

提供升学总览、保研／考研列表、具体机会详情与收藏。支持按升学类型、学校、院系、专业、招生年度、阶段和状态查找；具体枚举与分类需确认。搜索、筛选和分页可恢复；收藏沿用匿名阅读模式，并与新闻、竞赛身份隔离。

详情优先展示状态、关键期限、条件与材料、官方入口，再展示变更、经验帖和视频。未确定的时间不得生成精确倒计时；过去发布但仍有效的公告可正常查到，过期机会保留年度历史标识。

### AD-04 经验帖与视频

保研与考研均必须具备经验帖和视频区域，复用竞赛资源的字段、审核和失效管理。关联到学校／院系／专业／年度及备考或申请阶段；通用备考资源明确标记通用。区分申请经历、材料准备、初试备考、复试经验等内容，具体分类待确认。

旧年度经验明确年份和适用性；经验不能修改官方条件、承诺录取或生成录取概率。联系方式、成绩单、聊天记录等个人信息不默认采集或公开。无资源显示真实空态，并列入后台待补清单。

### AD-05 监测与变更

记录发现时间、官方发布时间、最后成功检查时间和业务日期。持续检查新通知与原文修改，识别截止延期、材料增补、考核／入口变化和撤销；过滤导航、浏览量等无关变化。无法访问和没有新通知分别展示。申请季／非申请季频率、处理预算、首次发布与关键变更核验策略待真实样本验证后确认。

### AD-06 验收

- 对确认的首批来源分别跑通保研与考研：官方公告→采集／解析→结构化与核验→展示→修改／撤回。
- 跨学校、院系、年度、批次不混淆；学校总通知不覆盖院系特殊要求，经验帖不作为官方要求。
- 至少覆盖日期不完整、原文延期、附件失败、来源异常、过期机会和无资源场景；不伪造缺失信息。
- 两类详情均能查看对应经验帖和视频并跳转来源，筛选／收藏／手机返回流程正常。
- 首批名单、资源覆盖目标和真实运行频率确认后形成逐项验收表，不用少量夹具代替全范围真实验收。

## 5. 工作板块三：整站UI重构

### UI-01 页面范围

统一设计学生首页、行业／世界资讯入口、竞赛总览与列表／详情、保研／考研总览与列表／详情、收藏、资源区域、移动端导航及渠道接入入口。首页分区呈现资讯、近期机会、重要变更及精选学习资源，不将所有内容混成按时间排列的单一信息流。

桌面导航、手机底栏、首页区块和详情结构先形成可审查方案；具体布局、配色、站名、Logo和阅读密度由使用者确认，不把本文建议当成最终视觉稿。

### UI-02 内容组件与交互

新闻卡片强调来源、摘要和进展；机会卡片强调类型、年度、适用对象、状态及期限；资源卡片强调经验／视频身份、作者、平台、适用范围和原平台入口。官方信息与经验资源有明确文字区分，状态不只依赖颜色。

保留现有深浅主题、搜索筛选、分页、返回位置和收藏能力；改地址时提供明确的旧链接兼容方案，不能使既有详情、收藏和分享链接失效。提供加载、空结果、未收录、待核验、访问失败、过期和撤回状态。

### UI-03 手机与无障碍

手机优先保证期限、适用范围和官方入口可见；适配长标题、长链接及多范围日期，避免横向溢出。支持键盘访问、可见焦点、清晰标签和合理触控区域。外部视频不自动播放、不阻塞正文加载；QQ／微信内打开、原平台跳转和返回行为纳入实机验证。

### UI-04 验收

先确认页面原型与组件规则，再实施；检查桌面和至少390px手机视口，并在实际手机浏览器与目标渠道内验证。验证首页到详情、筛选返回、收藏、深浅主题、错误／空态、键盘操作和旧链接回归。实施时明确可量化的性能与无障碍检查项，不能只以截图接近作为全部验收。

## 6. 工作板块四：手机QQ／微信接入

### MSG-01 目标与能力验证

让学生在手机QQ／微信中访问平台，并通过经验证的官方渠道查询资讯／机会，或接收支持范围内的新公告、变更和截止提醒。以下能力分开记录：网页分享与打开、消息查询回复、群级通知、个人订阅与绑定；不能把可打开网页视为完成通知接入。

QQ的群／频道／个人场景、微信的普通聊天／企业微信／公众号／小程序场景尚未确定。先列出实际账号类型、权限、审核、消息限制、费用和实测结果，再由使用者选择首版形式。实施时核对最新官方文档，不沿用旧稿中的平台政策作为当前事实；不承诺未经验证的主动推送，不采用非官方个人客户端自动化。

### MSG-02 查询与分享

在支持消息查询的渠道提供资讯、竞赛及保研／考研查询，结果带摘要、当前状态和网站详情链接；具体指令与会话方式在能力验证后确定。手机分享卡片能正确展示标题和平台身份，无法唤起外部应用时提供可操作的网站链接，不误报发送或打开成功。

### MSG-03 订阅与提醒

在实际支持且用户同意的渠道，支持按板块、竞赛、学校／院系或主题订阅。机会提醒覆盖新公告、关键变更和临近截止；频次、提醒提前量、免打扰时段由使用者确认。提供取消方式，避免重复事件、同一版本和同一提醒阶段重复发送。

发送前重查当前展示版本、期限、撤回和订阅状态；延期后旧提醒失效，重新按新日期计划。投递保存成功、失败和未知状态；超时不能直接按未发送重发。消息区分“首次发现”与“官方刚发布”。普通用户身份与管理员身份分开，群级通知也不能默认为个人订阅；需个人绑定时另行设计最小账号与隐私机制。

### MSG-04 管理与验收

后台提供渠道配置、连接／权限状态、投递记录、失败原因、停用入口及订阅管理；不在公开接口、前端或日志输出密钥和私人订阅信息。测试使用假服务，不向真实群发消息；真实试发对象与范围须获使用者授权。

分别对QQ和微信保存真实账号能力矩阵及端到端证据。首版选定的每种渠道都需完成手机打开／查询或订阅→收到结果→跳转网站→取消的适用流程；验证去重、免打扰、过期／撤回检查和未知结果处理。确实不支持的能力列明限制和由使用者确认的范围调整，不把只完成一个渠道写成两个都完成。

## 7. 共享能力与工程边界

| 共享对象 | 需求契约 |
| --- | --- |
| 资源 | 稳定身份、类型、标题、来源URL、作者／平台、已知时间、摘要依据、可用性、审核及修订记录 |
| 资源关联 | 资源身份、竞赛／升学目标身份、适用年份／届次／阶段、关联说明；一个资源可有多个准确关联 |
| 升学机会 | 学校、院系、专业／项目、招生年度、保研／考研、阶段／批次及来源证据；具体表结构另行设计 |
| 通知事件 | 目标对象及当前版本、事件／提醒阶段、适用期限；与渠道投递及私人订阅分开 |

表格是业务契约，不强制提前创建表或抽象。先查现有实现，竞赛与升学共用必要资源能力，不复制两份资源管理；领域规则留在模块。前端只经HTTP读后端，全部公开出口从统一publication读取，撤回和权限各出口一致。普通用户数据不进入公开API。

页面阅读不触发模型；付费任务走既有回执及预算。当前新闻每天5元策略不自动扩展为本轮资源、升学或视频费用授权，各新增任务预算先明确。开发默认关闭采集、模型及推送，测试连本地假服务；真实来源验证与真实渠道试发分别记录。迁移、附件权限、Git和部署遵守根目录AGENTS.md及[架构](architecture.md)、[部署](deploy.md)约定。

## 10. 开发前需要共同确定的事项

- 经验帖／视频：优先平台与作者、允许的获取方式、重要性／噪声标准、首批31项覆盖目标、核验和更新责任。
- 保研／考研：首批学校／院系／专业、公告类别、是否包含本校推免资格、考研专项字段、分类与监测频率。
- UI：站名、Logo、参考风格、导航名称、首页信息密度；先交付方案供使用者确认。
- QQ／微信：群／个人／频道／公众号等具体场景、可用账号、优先查询还是提醒、测试对象与账号绑定需求。
- 运营：新增采集／模型／存储／通知预算、发布及变更核验策略、提醒频率、条款与隐私说明。

这些未决项不阻止编写契约、整理样例或制作方案，但不能自行变成生产默认值。本次只合并需求与协作入口，不实施功能、不启动已停服务、不扩大真实付费或发送范围。
