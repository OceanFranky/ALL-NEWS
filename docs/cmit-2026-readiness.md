# 2026数媒竞赛：作品差距与三人交付计划

核对时间：2026-10-17；10月18日交付。以现有仓库、线上升学预览和本轮实际检查为依据；以下差距判断是项目建议，不是专家打分或获奖承诺。

## 建议结论

当前项目已经有可运行基础，但尚缺足以支撑“全国一等奖水平”的原创性、用户价值和展示证据。最值得做的是将**用户自选官网 → 后台采集与有据整理 → 目标对比 → 材料准备**做成清晰、可信、可复现的完整体验。

建议以“大学生升学信息整理与申请准备工具”作为本次作品主线。新闻与竞赛模块可以保留，演示围绕一个升学任务展开，避免四个板块平均介绍。作品正式名称由团队决定；当前NEXUS与AI行业文案仍需统一到团队确认的定位。

按已查阅《参赛指南》正文第10—11页，推荐报名候选为**自主选题类 → 移动与网络应用开发类赛项**，其范围明确包含Web应用、信息系统和校园服务应用。最终以报名系统实际选项和团队确认结果为准；使用AI不等于应选“AIGC视觉创作”赛项。

## 现状边界：申报时可以与不可以怎么说

| 可以核对的事实 | 不应扩大成的说法 |
| --- | --- |
| 现有目录112所历史211高校、116办学条目，含39所985 | 已覆盖所有一本或所有招生院系 |
| 上轮发布97条公告，包含9校12条具体院系／项目范围 | 全39所985的每个学院与专业要求均已结构化 |

| 原文依据、未知字段、机器整理身份与撤回机制可见 | AI摘要等于学校资格审核或录取结论 |
| 来源支持定时检查，整理仍受模型与预算状态限制 | 任意新链接提交后立即、无限、免费完成整理 |
| 收藏与材料勾选保存在当前浏览器 | 已有跨设备账号同步、微信通知或云端提醒 |
| 5元累计保守记账约4.961002元，用户不追加 | 本轮可以继续演示大批真实模型提取 |

因此现场应分别展示“现有真实结果”和“新来源的真实处理状态”。额度不足、访问失败、待模型等状态必须如实展示。不能把已整理记录伪装成刚刚生成，或将虚构示例用作真实招生依据。

## 本轮代码优化

收藏页改为升学准备工作台，保留原入口与本机收藏格式。

1. 引导收集官网、比较目标、准备材料三个步骤。
2. 从收藏中选择最多3条公告，并列比较院系／专业／批次、年份／路径／阶段、学位、开始与截止时间、申请条件、官方来源和检查日期。
3. 不同路径／年份／阶段给出范围提示，未知要求保持未知；真实公告和虚构演示分开选择，不在同一组对比。
4. 对比目标下直接勾选材料，复用详情页版本化清单；取消收藏、撤回或读取失败的公告不继续保留在当前对比中。

实现位于`modules/admission/web/saved.tsx`和`preparation.tsx`，浏览器行为测试为`apps/web/tests/admission-preparation.test.ts`。不新增后端任务、模型调用或数据库迁移；对比选择仅用于当前页面会话，收藏和清单按原规则持久保存。

## 可直接执行的用户测试

这是一套建议验证方案，不是已经做过的实验，也不是赛事强制样本量。

- 对象：6—8名确实有保研或考研需求的学生，匿名记为U01等；不要只找开发组自己操作。
- 材料：固定同一批已核对公告，记录URL、年份、院系、批次和版本；先由成员A建立官方原文答案。
- 任务：找出一个目标的适用人群和截止信息；对照两个目标的条件差异；发现一个未知字段并回查原文；列出所需材料并勾选一项；添加一个官方来源并解释其当前状态。
- 对照：让一部分用户先直接查官网、一部分先用平台，使用两组难度接近的公告，再交换方式，减少熟悉顺序造成的偏差。
- 记录：任务成功／失败、完成用时、误把年份／院系／机器摘要当事实的次数、求助次数、最不理解之处、匿名原话。失败也保留。
- 汇报：给出每人的原始值、成功人数／总人数、用时中位数与范围；小样本只说明这批任务的效果，不推断全体学生。没有测出的优势就不写“效率提升XX%”。

记录模板：

| 用户编号 | 使用方式与任务顺序 | 公告URL与版本 | 任务 | 是否正确完成 | 用时秒数 | 求助／误读 | 用户原话与改进 |
| --- | --- | --- | --- | --- | ---: | --- | --- |
| 待真实填写 | | | | | | | |

人工内容核验单独记录学校、年份、路径、院系专业、申请条件、材料、完整日期／时刻、依据原句和未知字段。只报告实际核对了多少份、多少字段正确、错了什么；不要拿测试用例通过数冒充招生信息准确率。

建议准备三类证据：

## 材料与实录建议

按10月15日规范：报名信息必填、承诺书和不超过10张真实截图必交；作品评审视频与汇报PPT至少二选一，优先推荐视频；参赛压缩包必须包含实际作品成果。第三方资源和AI使用按实际情况说明。视频／截图不能替代真实作品。

专家评审材料需匿名化：截图、视频、PPT、文档及专家可见目录中处理学校、团队、姓名、指导教师等身份信息；原文大学名称属于产品数据，不等同参赛学校署名。项目GitHub账号、浏览器头像、提交作者和网址等若会泄露参赛身份，也需检查处理，同时保留必要开源许可。资格审核材料按系统指定渠道提交。

建议评审视频采用以下叙事，时长不是官方规定：

1. 用一个学生真实任务说明问题：在两个官网间核对当年、本院系要求。
2. 实录一条官方来源及其真实状态，说明后台采集、证据提取与费用控制。
3. 对比两个真实目标，主动指出年份／阶段差异与未知字段。
4. 回到原文核对，勾选材料、刷新验证、展示版本变化处理。
5. 展示架构、自研边界、真实用户测试和当前限制，分别讲清三人贡献。

评审视频强调为什么、如何做和原创贡献；作品展示视频强调实际交互，两者可复用实录素材。功能尚未完成、模型等待或仅演示夹具的地方应明确标注。最终格式、时长、容量和赛项专门要求在报名系统核对，不按本建议自行推断。
