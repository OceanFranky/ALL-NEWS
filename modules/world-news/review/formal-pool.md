## 标注顺序

1. 阅读本机 JSON 的 `material.title`、`material.excerpt`、发布时间和来源。RSS 没说的事实不补；要用新增材料则另建修订，不能悄悄替换快照。
2. 先按初审 [samples.md](samples.md) 的格式判断相关性、材料充分性、主分类、内容类型、精选价值和理由。初步标签可以另保存在本机 JSON，不能由模型答案代替人工金标。
3. 确认具体事件的 `eventGroup`：同一事件及直接进展整体分集，不按国家、战争或大主题一锅归组；噪声样本也使用可核对的组号。
4. 以事件为单位分开发／留出，目标 80／20，已看过的事件只进开发。保证两边都有该选／不该选材料；若样本缺重大事件、分析评论、矛盾说法或边界题材，先补换，重新冻结索引和快照，不凭日期或编号随机切。
5. 冻结规则和开发标签后，用世界新闻独立执行结果填写 `result`。保留提示词版本、模型配置、材料修订和回执对应；不能引入 AI 行业评测标准。
6. 整理成 [calibration.md](calibration.md) 的输入，开发集选门槛，留出仅验收一次。UNKNOWN／不足／失败原样保留。现在所有 gold、eventGroup、split、result 均为空，尚不能运行真实校准。

## 可复跑的只读导出

先检查专用 Docker 测试容器的实际映射端口，再把它填入 `DATABASE_URL`：

```bash
DATABASE_URL=postgres://postgres@127.0.0.1:54512/world_real_trial_test node modules/world-news/scripts/prepare-review.ts
```

默认只输出 Git 索引；增加 `--private` 输出包含原材料的完整候选池，输出只供本地审查，不要提交。脚本只读指定本地试验库，不读取密钥、不迁移、不采集、不调用模型、不更新生产状态。
