# 竞赛模块前后端数据对齐与开发指导

日期：2026-10-15（Asia/Shanghai）。适用分支：`codex/competition`。

本文指导候选入库之后的后端服务、三层前端及后续增量更新开发。本文是开发契约草案，不表示接口、发布机制或页面已经实现；标为“待确认”的产品规则不得自行变成生产默认值。

2026-10-15实施追加：使用者确认现有31项校验通过候选首次展示，后续修订另行选择。候选查询、稳定届次及展示版本、公开列表／详情／筛选和时间状态已实现，实际契约以[API说明](API.md)为准；本文阶段表保留规划背景。首版显示全部已选定届次、按名录身份排序，不新增重要性评分；总览及增量生产仍待实施。

## 1. 当前阶段与本轮目标

官网发现／核对 → 材料采集 → 解析 → 模型提取 → 校验／有限修正 → PostgreSQL候选入库，已按现有31项完成阶段验收。31项有候选，31项结构及原文引用校验通过；24项基础可审核、2项字段全known、3张宣传图known。这不是全部当届信息齐全或语义完全正确的证明。复杂来源有Agent辅助定位、纠正，完全陌生名录与长期无人值守未充分验收。

本轮先把现有候选组织成稳定可查询的数据服务，再实现页面，最后验证每日增量运行。**缺宣传图、未全部字段known，不阻塞数据服务或前端开发。** 不以要求使用者逐条人工审核作为本轮开发前提；公开展示哪些候选及如何更新，须单独确定规则。

现有事实以[最终验收报告](verification/2026-10-14-final-ingestion.md)、[实际工作流](WORKFLOW.md)、[字段schema](backend/schema.ts)和[入库实现](backend/repository.ts)为准。视觉布局参考[前端指南](../../docs/competition-frontend.md)，本文负责数据契约；旧规划中的“尚未采集／入库”描述不代表当前状态。

## 2. 开发边界

- 只使用已批准的名称、年份、宣传图片、分类、学校认定级别、人数限制、指导老师限制、报名时间、比赛时间、赛段、官网、文件、简介。状态、节点、倒计时是这些字段的派生结果。
- 级别来自学校名录；保留主体及专项差异，不推断全国统一级别。分类复用现有11个批准标签，不增设生产标签。
- 费用、主承办方、学历／年级／专业、地区、奖项、独立报名链接不新增为读者业务字段或筛选条件。
- 竞赛页面只经HTTP读API；公开出口统一经 `packages/backend/src/publication/`。模块业务留在 `modules/competition/`，不复制新闻写作、评分或热度流程。
- 查询、搜索、筛选、刷新和日期计算均不触发采集或模型；付费工作只在worker，继续使用回执和预算。
- 本文编写及后续本地开发不自动启用采集、模型、推送或常驻任务，不扩大已授权的两轮验收预算。

## 3. 页面与数据需求

### 3.1 竞赛总览 `/competitions`

| 区域 | 后端需要提供 | 前端职责及边界 |
| --- | --- | --- |
| 正在进行 | 展示版本的简卡、分范围报名／比赛状态、下一节点 | 报名和比赛可同时显示；不能用“进行中”暗示仍可报名 |
| 近期节点 | 节点类型、官方名称、范围、精度、日期、详情身份 | 明确报名截止／比赛开始等类型，不能混成同一种截止 |
| 重点竞赛 | 使用者指定的重点范围及有依据的展示理由 | 重点名单／排序待确认；未配置时不伪造推荐或热度 |
| 分类入口 | 批准分类、当前可见结果数量、对应筛选条件 | 多分类可重叠，分类计数之和不等于竞赛总数 |
| 重要变更（后续） | 已展示修订间的字段变化、范围、依据、发生时间 | 不把抓取失败、OCR变化或所有新候选都显示为正式变更 |

正在进行与近期节点使用同一套后端派生逻辑。总览窗口、条数、重点名单、排序和“即将截止”天数待确认；开发可用明确标注的夹具，不自定重要性分值。重要变更在版本与差异机制完成后接入。

### 3.2 全部竞赛库 `/competitions/library`

卡片数据：稳定详情身份、名称、年份原文、图片或缺图状态、分类、学校级别及适用范围、简介、人数／教师限制摘要、分范围状态、下一节点与日期精度。摘要由原字段确定性整理，不能调用模型新增判断；多范围不能只取第一条冒充全赛事规则。

| 行为 | 前后端约定 |
| --- | --- |
| 名称搜索 | 按名录名称及展示名称匹配；不顺带增加全文检索或搜索索引系统 |
| 筛选 | 首版实现分类、学校级别、年份、派生状态；赛段精确筛选后置，现有自由文本不能冒充规范枚举 |
| 组合条件 | 不同筛选维度取交集；同一维度多选取并集；分类允许多归属；级别匹配需保留主体／专项范围 |
| 筛选面板 | 默认收起，有重置／确定；确认后写入URL，取消单个条件也同步URL |
| 分页 | 服务端分页；返回总数、页码、页大小；稳定排序追加内部身份作为并列判定，不先全量下载再前端筛选 |
| 排序 | 排序枚举及默认值在接口落地前确认；不默认将学校级别视为重要性评分 |
| 年份／历史 | 提供年份选项；年份不明单独表达；当前届／历史届切换依赖第6节身份设计，不把旧届自动改成年份今年 |
| 返回恢复 | 关键词、条件、排序和页码保存在URL；滚动位置由前端恢复 |
| 跳转 | 标题或整卡进入详情，支持键盘；不恢复右侧“查看详情／官网”按钮 |

结果单位建议为“一个具体届次的展示记录”，不是材料、修订或赛段；接口实现前冻结。总数和分类数量只计算同一公开可见集合，不把内部31条候选数当作公开结果数。

### 3.3 竞赛详情

建议稳定地址为 `/competitions/:competitionId/editions/:editionId`；该地址尚未实现，须先落实届次身份。不得使用年份或revisionId充当稳定届次身份。

| 区域 | 数据 |
| --- | --- |
| 顶部 | 名称、年份、图片状态、学校认定及范围、分类、状态与下一节点 |
| 时间线 | 报名／比赛各时间条目，保留label、scope、officialText、precision、timezone、start、end |
| 限制 | 人数和指导老师限制的原文、人数口径、上下限、适用范围；未知上限不等于不限 |
| 简介与赛段 | 已有简介和赛段原文；无法关联的赛段不硬配时间／人数 |
| 官方入口 | 已确认且允许展示的官网；未知时显示说明，不猜域名，不另设报名按钮 |
| 官方文件 | 当前schema已有title和url；未取得机构、发布日期、大小、类型时不凭文件名推断或强制新增采集字段 |
| 来源与更新时间 | 可公开来源链接；材料读取时间与展示版本发布时间分开，不能把抓取时间标成官方更新时间 |
| 历史届次 | 同项目其他可见届次身份与名称，保留可访问链接 |

缺图使用文字布局，不生成冒充官方的海报；删除原规划的独立“相关链接”卡片。收藏入口属于历史页面意向，须先核对现有模块收藏能力及身份隔离；本轮查询服务不默认新建账号／收藏后端。

## 4. 现有库字段到接口的映射

原始候选 `data` 包含字段封装 `{ value, status, reason, evidence }`；学校级别由程序从名录合并。公开DTO采用显式白名单映射，不直接透传整份JSON或数据库行。下表中的公开字段名称为拟定契约。

| 现有来源 | 拟定公开字段 | 整理规则 |
| --- | --- | --- |
| catalogue.id／name | competitionId／catalogueName | 名录身份稳定，不等于届次身份 |
| revision.id | revisionId | 作为展示内容版本，用于可追溯及缓存，不作为详情地址 |
| data.name | name | 含届次；未核验名称不能替代名录的项目名称 |
| data.year | year | 保留primary及officialText，不用抓取年份补值 |
| data.promotionImage | promotionImage | URL、状态及已核实来源；无图可正常阅读 |
| data.categories | categories | 只返回批准标签；标签文案来自现有taxonomy |
| data.schoolLevel／schoolLevelByScope／schoolRecognitionText | schoolRecognition | 不丢专项差异；学校名称及认定有效年份未提供，不编造 |
| data.participantLimit／teacherLimit | participantLimit／teacherLimit | 保留scope、text、minimum、maximum、counts |
| data.registrationTimes／competitionTimes | registrationTimes／competitionTimes | 分开返回，不扁平化为单个deadline |
| data.stages | stages | 目前是字符串数组，不已有结构化阶段ID和关联表 |
| data.officialWebsite／files | officialWebsite／files | 官网身份确认与文件来自官方附件链分别核查，URL引用校验不等于身份／许可确认 |
| data.introduction | introduction | 不重新调用模型生成另一份介绍 |
| 材料／展示元数据 | provenance／publishedAt | 公开仅必要来源URL与可核实时间；内部材料块、任务报告不透传 |
| 时间派生（待实现） | activity／nextNodes | 携带适用范围、计算时间及精度，不写回模型事实字段 |

DTO建议分为 `CompetitionCard`、`CompetitionDetail`、`CompetitionOverview`、`CompetitionFilterOptions`；共用字段语义，列表缩减内容但不改变含义。接口schema、后端映射与前端类型使用仓库现有契约组织方式，不再手工维护三套互不关联的类型。最终类型和示例JSON在实现接口时提交，本文不声称这些类型已存在。

### 缺失值与错误表达

| 状态 | 页面表达 | 禁止行为 |
| --- | --- | --- |
| known | 显示已核验值 | 不隐去范围或日期精度 |
| unknown | 待核验／资料不足 | 不说官方没有公布 |
| not_stated | 已查材料未说明 | 不扩大成所有官网均未说明 |
| not_applicable | 不适用，附必要说明 | 不仅凭赛事类型猜测 |
| pending | 待公布，保留官方表述 | 不自动生成日期 |
| conflict | 信息冲突／待核验 | 不任取一方当确定值 |

公开reason需整理为适合读者的说明，不能泄露模型返回、堆栈或内部调查细节。基础校验valid／readyForReview只留内部，不作为正确率徽章。请求失败、合法空结果、未知字段是三种不同状态：错误不能包装成空列表。

## 5. 时间与派生状态规则

- 时间计算由后端统一提供 `computedAt`，测试注入固定时间；列表、详情、总览使用同一计算器。展示按条目的timezone解释，不能依赖服务器所在时区。
- 报名与比赛分别计算，按scope保留多组活动状态，可同时“比赛进行中”和“部分赛段可报名”。没有完整规则时不推断个人参赛资格。
- minute精度按实际时刻；day精度保留自然日语义，区间起止包含关系须在实现前写入契约并测试。月份／大约时间只展示原文，不生成精确倒计时。
- 只有截止、没有开始时间时，可显示“已公布截止日期”；不能因此断言已经开放报名。缺结束时间不能无限期判为进行中。
- 下一节点按可确定的未来时间组织，保留类型和范围；并列节点不丢失。倒计时只有日期足够明确时才返回，并说明按自然日或时刻计算的口径。
- 某个已知赛段结束不等于全赛事结束；只有已知节点不再位于未来，也不能推断未取得的后续赛段不存在。读取失败不改变赛事事实状态。
- 没有新材料也会跨越时间节点；派生状态查询时计算或按既有缓存机制更新，不为跨日触发模型或创建内容修订。缓存不得让过期报名状态长期保留。

## 6. 稳定身份与展示版本

### 已有与缺口

现有 `competition_catalogue` 是项目名录，`competition_revisions` 是候选修订，`competition_materials` 是材料快照；另有运行、来源及费用记录。修订表虽允许approved／rejected状态，但当前只有候选保存流程，尚无完整批准、撤回和当前展示版本机制，也没有独立稳定届次实体。

实施前先设计“项目 → 届次 → 修订 → 当前展示版本”。一个项目可跨年、多届；年份用于筛选而非唯一键；同届多个赛段保留其范围，不能把任何赛段都自动拆成新届。历史材料、错误修订和预算记录保留。

### 展示与更新契约

1. 内部读取最新候选与当前展示版本分开；公开列表、详情、筛选和总览统一读取展示版本。
2. 先实现管理员可查看候选、缺口、来源、修订差异的查询能力，不把所有原始候选默认公开。内部预览也需要管理员权限。
3. 展示选择绑定具体届次和revisionId，记录执行者、时间及依据；支持明确撤回。批准／撤回流程需要验证竞赛、届次和修订归属并原子更新。
4. 发布规则单独待确认：首次发布是否自动、允许哪些缺失／冲突、关键变化如何进入展示版本。不能将valid、readyForReview或“最新一条”直接等同发布许可；不默认让使用者审核31项才继续开发。
5. 新候选失败、退化或来源不明，不覆盖已有展示版本；不要跨修订临时挑字段拼成没有记录的新内容。确需合并时形成可追溯修订。
6. 新届尚未形成可展示版本时，不把旧届改成今年；旧届是否默认出现在列表／总览由产品规则决定。

迁移使用新的在线单语句文件，索引遵守CONCURRENTLY要求，不改已发布迁移。历史31项的届次关联应先产出可核对映射与异常清单；批量回填不塞进发布迁移，不在未确认归属时按year自动分组。

## 7. 拟定HTTP接口

以下路径是实现目标，当前不存在。先搜现有模块、鉴权、错误及分页模式，按仓库约定落地，不另建一套基础框架。

| 接口 | 用途与主要返回 |
| --- | --- |
| `GET /api/v1/competitions` | 列表：items、total、page、pageSize、computedAt；拟定参数q、category、schoolLevel、year、activity、sort、page、pageSize |
| `GET /api/v1/competitions/filters` | 批准分类、名录级别范围、可见年份与支持的状态／排序；明确计数是否受当前筛选影响 |
| `GET /api/v1/competitions/overview` | 正在进行、近期节点、分类入口；重点及重要变更按已确认策略分阶段接入 |
| `GET /api/v1/competitions/:competitionId/editions/:editionId` | 当前展示详情、revisionId、来源、缺失说明、派生状态及其他可见届次入口 |
| 管理员候选列表／详情接口（路径实现时确定） | 最新候选、validation、缺口、材料、修订、运行及预算只读查询；不与公开DTO混用 |
| 管理员版本操作接口（路径实现时确定） | 选择展示版本、拒绝／撤回；需既有管理员鉴权及CSRF，并校验提交所针对的版本 |

参数错误返回明确的400；未知／不可公开的详情返回不泄露内部状态的404；服务故障返回符合仓库规范的错误。稳定并列排序、页大小上限、重复参数编码、空关键词、大小写及非法枚举要在接口schema和示例中冻结。未知分类／级别不得静默当成无筛选。

公开管理员与访客看到同一内容；管理员候选预览使用独立受保护接口。公开DTO排除run报告、模型响应、费用、回执、内部存储位置和密钥。来源展示只给经整理的公开依据，不开放整库材料下载或任意URL代理。

## 8. 增量更新闭环（后续阶段）

现有02:20调度声明、材料指纹、无变化跳过模型及预算停止逻辑继续复用，不重写采集Agent。

1. 检查已确认来源及关联材料，保存变化快照；失败保留已有展示内容。
2. 有变化才进入受预算约束的解析、提取、校验与有限补查；对已有缺口的重提取仍须显式授权，不能以每日任务无限付费补齐。
3. 关联同届或新届；无法确定身份时保留候选，不自动覆盖或创建错误届次。
4. 计算同届同范围字段差异，区分正式变化、缺口恢复、候选退化与解析变化；引用相应版本和材料。
5. 按确认的发布规则更新展示版本，再由同一读取层更新列表、详情及总览；重要变更不能早于展示生效。
6. 不依赖新材料刷新日期状态，记录运行成功、失败、预算停止及最后检查时间；不额外调用模型写运行总结。

上线前单独验证Docker浏览器／OCR依赖、调度时区、局部失败、重启后任务执行行为及预算。长期费用与自动发布政策待使用者确认，当前验收预算不视为永久授权。

## 9. 开发顺序与交付验收

| 阶段 | 实施内容 | 可验收结果 |
| --- | --- | --- |
| A 候选只读服务 | 管理员候选列表／详情、字段投影、缺口及证据查询 | 现有31项可查；原始字段范围不丢；无模型调用；未确认发布策略也能交付 |

### 必须验证的重要行为

- 旧届不冒充今年，同年多届、局部赛段、主体／专项级别不混；详情地址不随修订变化。
- 报名与比赛同时进行、多范围截止、只有截止无开始、月级／大约时间、时区跨日、未知赛段均有真实边界样例。
- 无图、未知教师人数、缺官网、冲突字段、长标题及多个文件可正确表达，不新增采集门槛。
- 筛选前后total、分类计数及分页一致；并列排序稳定；返回恢复条件；内部候选不泄漏到公开结果。
- 新候选失败／退化不覆盖展示版本；归属错误、过期版本操作和未授权写入拒绝；撤回后所有公开入口一致不可见。
- 页面请求不采集、不调用模型；新闻六表与其他模块不被改写；现有31项材料、错误修订及预算历史保留。
