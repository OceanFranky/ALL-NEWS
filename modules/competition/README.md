# 大学生竞赛独立模块

日期：2026-10-14。分支：`codex/competition`。状态：官网到数据库工作流实现中；已接入站点后台模块与定时任务声明，日常安全阀关闭，尚无竞赛前端或公开发布。

使用者要求竞赛独立组织，参照世界新闻的三层浏览：竞赛总览 → 全部竞赛库 → 具体届次详情。首批31个目录条目及学校认定已保存至[名录说明](catalogue.md)和[名录JSON](catalogue.json)；分类按学科方向、允许重叠，11个标签于2026-10-14获使用者确认，见[分类配置](backend/taxonomy.ts)。重要性标准待讨论，学校名称与认定有效年份尚未提供。

HTML解析保留有说明的图片src、原始alt/title和外层公告链接，最多100个image-N-metadata证据块，不能从URL年份推断届次。图片说明需要与正式本届公告交叉核对；缺少说明仍仅保存图片候选。HTML快照hash包含解析证据，解析升级保存新快照，不覆盖旧引用。真实CCSP2026主视觉已据官网说明、关联公告及像素核对写入候选；OCR误读年份保留，不作为年份依据。图片仅保存官方链接，公开展示及许可审核仍在后续阶段。

懒加载图片优先读取HTML实际声明的data-original／data-src，再取src；缺失／空属性不解析为网页自身地址。占位图、通用标识、现场照片不能当宣传图；页面alt年份与图片实际届次冲突时不以公告日期覆盖图片内容。保留原URL和说明，不猜去掉缩略尺寸后的大图地址。

## 第一轮开发规范：只收录以下信息

使用者于 2026-10-13 明确限定第一轮范围。以下清单优先于此前规划和概念图中的字段建议；提取、数据结构、公开接口、筛选和页面展示均按此范围设计，不自行增加竞赛业务字段。

| 信息 | 要求 |
| --- | --- |
| 名称 | 完整竞赛名称，届次包含在名称中，不另设读者端届次字段 |
| 年份 | 单独保存竞赛所属年份，用于判断是否为今年的竞赛；不能用抓取年份代替 |
| 宣传图片 | 尽量取得对应竞赛的真实宣传图片，保留来源；缺图不冒充官方生成 |
| 分类 | 已确认按学科方向、允许多分类重叠；仅使用backend/taxonomy.ts的11个批准标签，不自动增删 |
| 级别 | 按使用者提供的学校认定标准处理；不同学校可能不同，不能自行套用全国统一级别 |
| 人数限制 | 记录官方说明的人数要求及适用赛段，不扩展为学历、年级或专业限制字段 |
| 指导老师限制 | 记录官方说明的指导老师人数或限制要求 |
| 报名和竞赛时间 | 必须收录；准确区分报名时间与各赛段竞赛时间，保留官方实际日期精度，缺失待核验，不推测 |
| 赛段 | 记录官方明确的比赛阶段，与相应时间、人数及老师限制关联；不另行扩展完整赛制模型 |
| 官网链接和文件 | 尽量从官方来源取得官网入口与竞赛相关文件；优先提供官方文件查看／下载链接 |
| 内容简介 | 基于官方材料写简短介绍，不借简介变相增加未批准字段 |

第一轮不独立收录或展示费用、主办方／承办方、参赛学历／年级／专业、地区、线上线下、奖项、认可名单、独立报名链接等此前建议项。文件中出现这些信息不代表要将它们提取成字段；官方文件本身仍可链接。

状态、下一节点和剩余天数可由上述时间与赛段派生，用于已讨论的三层页面，不作为新增采集字段。内部身份、来源证据、材料修订和审核记录仅用于隔离与核验，不借此扩大读者内容范围；具体结构后续设计。独立实体身份可区分不同届，届次对读者仍包含在名称内。

缺失信息保留未知或待核验；“必须收录时间”不等于必须编出日期。后续新增业务信息须先由使用者明确决定。三张现有概念图不重绘，实施时忽略其中超出本清单的字段和按钮。

## 官网到数据库执行入口（实现中）

先设置独立PostgreSQL的 `DATABASE_URL`，运行根目录迁移脚本；迁移会包含本模块的专属表，不改写新闻业务数据。导入名单：

```bash
node modules/competition/scripts/import-catalogue.ts
```

已确认官方材料URL的单项提取入口如下；仅在已授权真实采集、模型调用及费用后，以单次进程环境启用安全开关。项目 `.env` 不需改成默认开启。

```bash
COLLECT_ENABLED=true MODEL_CALLS_ENABLED=true node --env-file=.env modules/competition/scripts/ingest.ts \
  --id competition-011 --url https://www.aicomp.cn/notice/notice-1/3618.html
```

当前真实费用预留只支持已核实价格的官方 `api.deepseek.com` 上的 `deepseek-flash`，使用共享模型回执和预算，再附加首轮10元人民币累计预留限制。没有配置价格的服务不调用；失败／重试也预留额度。此为本次授权验收批次，不代表后续自动任务的永久预算。

已返回可信用量的调用按高峰未缓存价格结算并释放未使用预留；未结算／缺用量的调用继续占用全部预留。数据库锁串行化额度检查，并发测试保证有效占用不超过10元。后台运行进程加载代码后不热切换该规则，旧批次停止后才按新规则续跑。

材料写入 `competition_materials`，任务写入 `competition_runs`，原名单写入 `competition_catalogue`，提取候选写入 `competition_revisions`，费用预留写入 `competition_model_allowance`。结果只入候选库；公开发布尚未实现。

`ingest.ts --id competition-XXX --auto` 可使用此前Agent调查到的候选入口，运行搜索与官网身份核对、链接选择、采集、提取、校验和一轮缺口补查。无需再次手填官网；目前候选入口来自已保存的研究记录，完全陌生竞赛的搜索结果自动选址仍待验证。搜索摘要仅是线索，身份候选不确认时保留失败记录。

批量执行 `node --env-file=.env modules/competition/scripts/ingest-catalogue.ts`，需同样显式启用单次采集／模型环境；逐项记录成功与失败，费用额度不足时停止。单次最多尝试8个材料地址，补查只允许模型选择已有页面的链接；某附件失败不会丢弃其他有效材料。来源状态和原文依据另存 `competition_sources`。

批量脚本的 `--ids competition-025,competition-026` 可指定失败项续跑，不重复整个名单。数据库查询验收入口为 `node modules/competition/scripts/audit.ts`，报告全部31项的最新候选、缺口、校验、材料／运行数量及预算。新通知只描述延期时，提取会读取此前修订的材料；同URL新内容替代旧版本，旧材料和旧修订保留可追溯。

动态读取使用本模块 `playwright` 依赖，本机需先安装其匹配的Chromium：在模块目录执行 `npx playwright install chromium`。浏览器请求经共享guardedFetch完成，每个网络请求仍检查公开地址及大小／超时限制；服务端不使用管理员浏览器登录态。当前Dockerfile已加入模块依赖清单，镜像的浏览器二进制及系统库安装仍需部署阶段验证。

`sources.json` 保存首次发现的种子入口。模块通过 `site/modules/server.ts` 接入 worker：北京时间每日02:20将31项排入 `competition.ingest`，优先读取数据库已确认来源，补充已发现订阅源。调度和队列执行均检查采集／模型开关，开发环境默认关闭；未启动后台常驻任务。首轮10元仍是累计硬上限，后续长期费用策略尚未授权。内容指纹与既有材料一致时记录 `completed/unchanged`，跳过模型；该状态只表示本次无变化，原候选的缺口继续保留。

动态网页等候首轮公开接口加载，再提取正文。POST只允许同源、64KB以内、已观察到的只读操作（index.do的matchlist/simlist/getmatch/matchinfo，news.do的tablist/indexnews）；报名、登录、提交及其他操作拒绝，cookie和authorization不转发。官网明确返回 `ua blocked` 时尝试无登录态浏览器读取；仍被拒绝则记录失败。

审计脚本除逐项缺口外，报告跨竞赛任务引用、孤立材料引用、规范化重名、未来抓取时间及字段已知率。`readyForReview`仅是基础证据／时间校验门槛，不等于全部字段完成或内容已批准。

原文校验失败时，流程将具体errors反馈给模型并最多修正一次，即使没有抓到新材料也执行；再次失败的修订仍留在草稿，旧修订不覆盖。`MODEL_CALLS_ENABLED=true node --env-file=.env modules/competition/scripts/repair-candidates.ts` 可在独立 `DATABASE_URL` 下逐项重提取最新校验失败候选，完全复用各自已保存的材料，并使用批准分类。修正调用仍受共享回执及首轮10元限制；供应商401／402／403账户拒绝立即停止修正或全名录批次。

失败字段修正仅接受errors对应字段；时间通用错误对应两组时间字段。返回多余字段会被拒绝，其余字段及证据由程序原样合并，修正后重新检查全部证据。这个修正只解决结构与引用，不代替字段语义或官方身份审核；改为unknown会增加真实缺口，不能算信息已补齐。验证码附件记录明确解析失败，不尝试自动解验证码。

来源正文明确声明“本站信息搜集整理自互联网”等聚合／转载属性时，官网身份直接记录candidate及匹配原文，不以模型confirmed覆盖；该页面仍可保存为调查线索。分钟精度时间按ISO偏移转换后的实际时刻比较先后，日期／月份保留相应精度，跨年赛程不自动归为错误。

验收按[全流程标准](verification/acceptance.md)检查；已验证AIC正文＋PDF、职业规划正文＋DOCX、iGEM动态正文、软件杯扫描规则及CCPC正式通知／手册的真实模型提取与PostgreSQL候选入库。最新31项均有执行记录、30项有候选、24项基础可审核，017仍获取失败；逐项读回和缺口见[本轮交付](verification/2026-10-14-ingestion-handoff.md)。使用者明确无需等24项人工审核，不以全字段known或补齐全部宣传图阻止候选库交付；异常不算采集成功，基础门槛不代表语义正确或公开发布通过。

第16项按2026-10-14使用者确认改为江苏省大学生数字素养与技能大赛，仅学生网络信息安全赛项、仍B2。`collectionScope`是内部名单约束，传入发现、提取和修正，保存于名录元数据，不新增读者字段；原照片名称仅留作溯源。不能混入教师组、人工智能应用赛项或旧届规则。单项、批量与每日任务均读取当前sources.json种子，历史调查文件不再作为运行配置；无种子时可进入有界自动发现。

附件支持文本PDF、DOCX、OLE格式DOC及ZIP内上述文档；ZIP最多100条、单文档展开8MB、总展开16MB，不允许越界路径，不解析嵌套压缩包，文件块保留entry与页码／段落定位。未支持的报名表XLS明确记录未解析，下载链接仍可保留，不宣称所有附件已读完。每日刷新保留当前配置入口，再补历史已确认来源，避免旧届通知取代新届入口。

文件材料hash包含下载内容和解析文本，解析升级新增段落时保存独立快照，不覆盖旧证据；入库校验读取已存数据库原文，拒绝内存与持久化原文不一致的引用。无变化判断比较材料快照编号，因此新解析结果不会因下载字节相同被跳过。

新通知提取时不沿用正文明确声明互联网聚合／转载的旧材料；旧材料留库供调查追溯，不作为新候选的继承依据。官方PDF自身URL可以列入文件下载，引用其正文标题；学科分类按材料内容映射批准标签，不要求标签与原文完全同字。官网身份引用仍须保留原文空格及PDF断字，否则记录candidate，不能放松引用门槛。

已有证据缺口复查：`MODEL_CALLS_ENABLED=true node --env-file=.env modules/competition/scripts/repair-candidates.ts --ids competition-011 --missing`。缺口复查必须显式给出ID，只允许更新原校验报告中的缺失／失败字段，不能扩展读者字段或自动扫全名单付费。材料从该修订material_ids及已有字段引用取并集，数据库读取仍限定同一竞赛；找不到同竞赛原文的引用仍校验失败。复查不采集新网页，材料缺失时应先走采集流程；执行受原10元预算和共享回执约束。

官网图片补查支持PNG／JPEG／WebP本地OCR：仅选择网页实际发现的图片URL，经guardedFetch读取，单图4MB、16百万输入像素，单次子进程45秒；超限、空文字、低置信度、SVG和多帧图拒绝。OCR引擎和中英文语言包随模块依赖安装，运行时不下载语言包、不调用外部识别服务，子进程不继承密钥环境，临时语言目录由父进程清理。结果保存为image/*; extracted=ocr材料及ocr-block文本，保留识别置信度；OCR可能识别错误，名称／届次／年份必须与官方通知交叉核对。图片上传路径日期不能替代图中文字，研究材料入库不等于已确认宣传图。

扫描PDF复用同一本地OCR工具，普通页优先文字层；不足40字符的页面触发识别，最多16页／文件、PDF输入8MB（网络采集仍4MB）、最长边2400像素、嵌入图16百万像素，整次PDF识别子进程180秒。页数／时限根据真实11页数学建模通知调整，仍拒绝超限文件，不自动截断。固定canvas依赖本地渲染，无系统Poppler依赖；子进程不继承密钥，语言临时目录结束／超时清理。空白／低置信度页拒绝，不把缺页解释为官方未说明；超过限制记录失败，不自动截掉剩余页。扫描材料标注application/pdf; extracted=ocr与逐页置信度、page-N-ocr-block定位，hash包含解析文字及类型。扫描页面不是宣传图，OCR置信度不是字段正确率；核心事实需与同届官网正文核对。
